Design mock-up — revision 2. Remotes in the library sidebar: browse the configured registries and pull from them. The maintainer approved revision 1 on 2026-11-16 and decided how pulled images are named; this revision applies that decision and the defaults chosen for the open questions. Sample data only: registry.lan.example and nas.example:5000 stand for private registries on the local network; the unemu/ listing shows the planned 1.2.0 generation (today registry.unemu.dev is empty — see Empty (today)); digests are the published sets’ where those exist and illustrative elsewhere; sizes are illustrative. Nothing connects to a registry or writes a file. The Library collections stay as the approved machines mock-up shows them, plus the Source column.

Changes in revision 2

  • Local tags of pulled images are full references with the registry host, Docker-style: registry.lan.example/private/media/monkey-island:1.1-vga-720k. The default registry keeps the short names it has today (open-at:1.2.0, unemu/media/freedos:1.4). Images made here have no host until pushed.
  • A Source column in the Remotes list and the library lists: the registry host, or local. Name shows the path; the full local tag is in the details pane, Contents… and Pull….
  • A second private registry, nas.example:5000, a whole-registry entry, holds a repository with the same path as one on registry.lan.example: both can be in the library, with no clash.
  • Local state and Newer available compare only within one registry and repository. The clash example is now a tag that changed on registry.lan.example after it was pulled.
  • Several tags can be pulled at once: Ctrl (⌘ on macOS) or Shift selects rows, and Pull… takes them one after another under one progress bar.
  • The open questions are decided; see Decided at the bottom.

Notes — behaviour to approve

  1. Sidebar. Library keeps its group and order. Remotes follows it: one node per registry in Tools › Preferences › Registries, the default registry first; under it the namespaces its entry names (for a whole-registry entry, the first path components the catalog returns); under each namespace one group per artifact type that has repositories: Machine images, Installation media, Firmware. The type comes from the manifest’s artifactType, or its config media type. A private namespace shows a lock until you log in.
  2. Get templates… maps to Remotes. File › Get templates… and the empty library’s Get templates… button become shortcuts: they select Remotes › the default registry › unemu/ › Machine images, listing it first if this session has not. The dialog is retired and its rules move here: a template row offers the tag latest names when that is one of the newest releases, else the newest release; Pull goes by the digest the row showed; a template already in the library says so; several are chosen with Ctrl or Shift instead of check boxes.
  3. What is read without pulling layers. The catalog (GET /v2/_catalog, paged with n and Link; zot lists only what the caller may read, so a stored login goes with the first request), each repository’s tag list, and the manifest of its newest tag: artifactType, the annotations org.opencontainers.image.title, description, vendor, licenses, version and source, and every descriptor’s size and redistribution mark. The other tags’ manifests are read when a repository is expanded or a tag selected. The edition, and a media set’s version, are not annotations today: the details pane reads them from the selected tag’s config record, a few KiB. No layer, cover or disk is fetched before Pull; the pane draws a placeholder cover.
  4. Local state, within one registry. A row compares only with the local tags of the same host-qualified name, the one Pull would write. In library: that tag names this digest. Not pulled: it does not exist; when the same digest is in the library under another name, the row says so and Pull fetches nothing. Newer available: the library holds an older tag of the same name and not this one. Local tag names another image: the tag Pull would write names another digest. With host-qualified names this happens only when a registry’s tag changed after you pulled it; version tags never move in unemupc, so another tool or a rebuilt registry moved it.
  5. How “newer” is decided. Machine images: Semantic Versioning 2.0.0 precedence of version tags; pre-releases count only when no release exists; aliases such as latest never count. Installation media sets: tags <upstream version>[-<edition>][-<format>][-rN] compare only within the same edition and format — upstream version by numeric parts, then the revision (no -rN means r1). So 1.4-r2 is newer than 1.4 and 1.5 newer than 1.4-r2, while 1.4-720k is a sibling of 1.4, never newer. Firmware packages: the tag is the package revision; a higher number is newer. Superseded 2026-11-17 by decision-38, point 6: sets and packages are tagged [<release>-]rN and no version is read out of a tag, so only revisions of one release compare (1.4-r2 newer than 1.4-r1); 1.5 is not newer than 1.4-r2, and a release alias reads by the revision it names.
  6. Pull and local tags. Pull writes the full reference as the local tag, Docker-style: host, path and tag (registry.lan.example/private/games/dune2:1.0.0, nas.example:5000/private/media/monkey-island:1.1-vga-720k). The default registry keeps the short names it has today (open-at:1.2.0, unemu/media/freedos:1.4-720k). Images made here (New machine…, Save as new image…, import) have no host until pushed (private/games/prince-of-persia:1.0.0, Source local), so one path on two registries, or on a registry and here, never clashes. A host-less name is also the default registry’s short form, as in Docker: the store records whether Pull wrote a short tag or the library made it, which is what the Source column shows. Pull never moves a local tag: if it already names this digest, nothing is fetched; if it names another image, Pull stops before fetching and asks for another tag. An older local copy stays, with the machines made from it. Blobs already in the store are not fetched again; the tag is written last, after every blob is verified.
  7. Store tag grammar. Local tags gain an optional host[:port]/ first component: a component with a dot or a port, or localhost, as reference parsing already decides. Today the store refuses a local tag with a registry host, and a port fails its component check. What stays short: the default registry’s pulls (with unemu/ dropped when one component remains, as today) and images made here.
  8. Pull and create machine… (machine images) pulls, then opens New machine from image… as the approved machines mock-up shows it. Pull and insert… (installation media sets) pulls, then leaves disk 1 pending in a drive of a stopped machine that takes the set’s format, for its next Start. It is offered only when such a drive exists; running machines use Media › Insert as today.
  9. Caching and refresh. Every registry request runs on the library worker. Nothing contacts a registry until you expand or select its node. The listing stays in memory for this session only and is never written to disk, so private titles land in no cache; a disk cache comes later, with the catalogue index. Refresh (F5 or the toolbar) lists the selected registry again; there is no timer and no background polling. After a pull the local states update from the store, without a request. Timeouts are Get templates’ short ones: 10 s to connect, 15 s per read.
  10. States. Loading: rows appear as manifests arrive, with Stop. Unreachable: one message with Try again; after an earlier listing in this session, its rows stay under a banner and Pull is disabled. Login required (401): Log in… opens Tools › Preferences › Registries on that entry; nothing is listed or kept. Empty: says nothing is published yet. Server error, or no catalog (404): one message, and Image › Pull by reference… still works.

Decided

  1. The type group is Machine images; under unemu/ the Type column says Machine template.
  2. Edition and media set version are read from the selected tag’s config record. No new annotations, so published digests stay as they are.
  3. Several rows at once: Ctrl (⌘ on macOS) or Shift selects them, and Pull… pulls them one after another under one progress bar, as Get templates does. Tags already in the library, and a tag whose local name holds another image, are skipped with the reason.
  4. Pull and insert… stays.
  5. The catalog is read 50 repositories a page; Next 50 › appears under the list when there are more.
  6. A whole-registry entry shows its repositories under their first path component (nas.example:5000 › private/ here).
  7. The listing is kept in session memory only; a disk cache comes with the catalogue index later.
  8. Newer available by name or by origin is answered by host-qualified tags: a local name belongs to one registry’s repository.
