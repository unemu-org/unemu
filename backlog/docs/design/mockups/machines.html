Design mock-up — approved by the maintainer on 2026-11-15, all “please confirm” items included. Machines as named, local instances of images: the image vs machine split in the library, its details panes, dialogs and menus. Sample data only: digests, sizes, sector counts and dates are illustrative. Actions are previews: nothing runs, saves, deletes or publishes. Built on the approved library, main-window, new-machine, save-as-image and firmware mock-ups; everything not shown here stays as they show it.

Image vs machine

Image≈ docker imageA complete machine that never changes: firmware, configuration, disks and CMOS. Named by repository:tag, identified by its digest, shared with Push… and Pull….
Machine≈ docker containerYour named instance of one image. Its changes (disk and floppy journals, CMOS, settings, inserted media) live beside the image. One image can have many machines. Machines stay on this computer.
Save as new image…≈ docker commitFreezes a machine’s changes into a new image you can share. Reset to image… throws the changes away; Delete machine… removes the machine as well.
Gaming mode≈ docker run --rmPlays a disposable copy of a machine. When it stops, you discard the copy or keep it.

Changes in this design

  • A machine is a named, local instance of one image. Today each image has one hidden workspace. Now you see machines, name them, and can have several from one image. Images stay immutable and shareable.
  • Sidebar: a Library group with Machines, Images (was All images), Installation media, Firmware and Machine files. Recently played and Favourites sit under Machines and list machines. The facets of the selected collection sit under it. A greyed Remotes group follows, collapsed and empty.
  • Machines list: name, source image (repository:tag and a short digest, marked when the tag the machine came from has moved or is gone), state, last run and the size of its changes.
  • Machine details: source image with a link, media per drive (the image’s and the machine’s), settings that differ from the image, a pending insert, last run, and Start, Gaming mode, Settings…, Insert media…, Save as new image…, Duplicate…, Rename…, Reset to image…, Delete machine… and Disk layers….
  • Image details: Machines from this image with links, and New machine from image…. Start on an image creates a machine when the image has none; otherwise it asks which machine to start, or offers a new one. Settings… (a new image revision), Layers…, Push… and Delete tag… work as before.
  • Save as new image… from a machine asks what happens to the machine afterwards: it moves onto the new image with fresh journals (the default, as today), or it keeps its changes on the old image.
  • Gaming mode starts a disposable copy of the selected machine, or of the image when an image is selected. When it stops, you choose Discard, Keep as new machine… or Keep as new image….
  • File › New machine… also creates a machine from the image it builds. You can opt out on the Name and tag step.
  • Menus: Machine adds Insert media…, Duplicate…, Rename…, Reset to image…, Delete machine… and Show source image. Image adds Start…, New machine from image… and Gaming mode. Edit adds Rename…, Duplicate… and Delete machine…. Changed entries are marked new or changed, and Help › Keyboard shortcuts lists the new keys.

Migration

  • Each existing regular desktop workspace becomes a machine named after its image’s title, with its changes kept (here IBM AT with DOS and Open AT 286). A one-time notice in Machines says so.
  • A workspace named on the command line keeps that name. Leftover Gaming-mode workspaces stay as Unfinished gaming session, with Keep and Discard.

Out of scope

  • Rebasing a machine onto a newer image or tag. A machine never follows a tag; for a newer image, start a new machine from it.
  • Machine export and import, and machines on a registry. Machines never leave this computer; to share one, save it as an image and push the image.
  • Remotes in the sidebar (configured registries, browse and pull). That comes after the MVP, in a separate mock-up.
  • The full insert flow for a stopped machine, which has its own design. This mock-up shows only where it starts and what it leaves behind.

Proposed — please confirm

  1. The sidebar is one Library group in this order: Machines, Images, Installation media, Firmware, Machine files. A Remotes group can then follow after the MVP. Until then Remotes is shown greyed, collapsed and empty, with “after the MVP — separate mock-up”.
  2. All images becomes Images. Recently played and Favourites move under Machines and list machines. At migration, an image’s favourite star and last run pass to its machine.
  3. Facets (Labels, Platform, Genre, …) sit under the selected collection. Machines are filtered by their source image’s metadata and by their own local labels.
  4. The library opens on Machines. Enter or a double-click on a machine starts it.
  5. Machine names are free text of 1–64 characters, unique ignoring case. The default is the image title, then “title (2)”. Each machine also gets a fixed workspace id for the command line (dos-games); Rename… changes only the name.
  6. Settings… on a machine changes that machine only. The change applies at its next start, is listed as Settings that differ from the image, and Save as new image… writes it into the new image. A memory or drive change recomputes this machine’s CMOS bytes, as on an image. Image › Settings… still publishes a new image revision.
  7. The State column uses: Never started, Same as image, Changed: A:, C:, CMOS, settings (drives in drive order) and Running, plus the badges insert pending, ⚑ tag moved and detached.
  8. Start on an image with no machine creates one named after the image title and starts it, without asking. With one or more machines it always asks, preselecting the machine run last, with New machine as the last choice.
  9. File › New machine… keeps its name and Ctrl+N and makes both the image and a machine from it. Its Name and tag step gains the machine name and an opt-out check box. There is no separate New image… command.
  10. Save as new image… from a machine moves the machine onto the new image with fresh, empty journals by default (as today). The other choice keeps the machine on its old image with its changes. The repository name defaults to the machine name as a slug, starting at 1.0.0, and the title to the machine name.
  11. Gaming mode on a machine plays a copy of that machine as it is now, so its changes are copied first. On an image it plays a fresh copy of the image. When it stops: Discard (the default), Keep as new machine… or Keep as new image….
  12. Duplicate… copies changes, settings, pending inserts and labels into a new machine on the same image. Reset to image… also drops a pending insert, and keeps the name, favourite, labels and last run. Delete machine… never deletes the image. Disk layers › Discard changes becomes the same Reset to image….
  13. New library keys, active only outside guest focus: F2 Rename…, Ctrl+D (⌘D) Duplicate…, Delete (⌘⌫) Delete machine… or Delete tag…, Ctrl+Shift+N (⌘⇧N) New machine from image…. Enter on an image opens Start….
  14. The Image menu acts on the selected image, or on the selected machine’s source image, and names that image at its top.
  15. Insert media… on a stopped machine opens the separate insert design. Its result, a pending medium, belongs to the machine and shows in its details and State until the next Start.
