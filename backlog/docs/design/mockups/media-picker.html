Design mock-up — revision 2, for approval. Revision 1 was approved by the maintainer on 2026-11-15, all “please confirm” items included, and stays as it was: one media picker for every Insert…, the Installation media collection’s Insert into… and Add to machine…, and pending inserts on stopped and halted machines. Revision 2 adds Create from files…: many DOS games, from itch.io for example, come as loose EXE files and folders, and the picker packs them into diskette images instead of a host tool. It builds on the approved machines, main-window and installation media mock-ups; everything not shown here stays as they show it. Sample data only: sizes, digests, dates and the host files and folders are illustrative, and actions are previews. Nothing runs, reads a file or contacts a registry.

Changes in revision 2

  • Create from files… in the picker’s footer, beside Browse for an image file…. It turns the picker into its Create view; the Into row (machine, drive, when) stays.
  • The Create view: Add files… and Add folder… (the system dialogs; drag and drop works too), the list of host items with sizes and × to remove, the top folder name, the format (only what the drive takes, its own first), the volume label, a fit meter that counts cluster rounding, folders and root entries, and the DOS (8.3) names and skipped files, collapsible.
  • Live states: fits; does not fit, with the bytes it needs beyond one disk; one file too large for any disk, named.
  • Too big for one disk: both options are shown. Split across N disks with its plan, the catalogue order for Next disk and the XCOPY command that rebuilds the tree on C:; Copy into C: greyed, “later”.
  • Create and insert stores the disk, or the set, as the machine’s own and puts it into the drive: now while running or halted, at the next Start while stopped. Also keep in the library as an installation media set is on for a split and off for one disk.
  • Mock-up controls open the Create view on sample folders. Notes and the maintainer’s decisions are at the bottom of the page.

Revision 1 — changes in this design (approved)

  • One Insert… per drive — from the Media menu, the drive chip’s menu, the toolbar’s A: and B:, and Ctrl+Alt+I (Shift for B:) — opens the media picker. It replaces both Browse / catalogue… and From library…. The old dialog’s raw store path, Refresh button and list of refusal reasons are gone.
  • At the top of the picker you pick the target: the machine (fixed while it runs), the drive (switchable, with its format and what is in it now) and when the disk goes in (now, or at the next Start).
  • Search: type to search, with facets for Format, Platform, Genre, Year, Publisher and Labels, and field:value words. Each result row shows a cover placeholder, title, publisher, year, genre, disks (“2 × 1.2M”), the number of extras and whether the set is open or private.
  • Fit follows the drive’s accepted media: a 1.44M drive takes 1.44M and 720K, a 1.2M drive takes 1.2M and 360K. Sets that don’t fit are hidden behind one “N don’t fit — Show” line. When shown, they are dimmed with one short phrase, such as “Fits B: — Alt+B”.
  • Set details in the picker: pick the disk to insert, put the whole set into the drive’s catalogue in order (for Next disk), and say in plain words what happens when a program writes to the disk.
  • Sources: This machine (disks already in its catalogues) and This library. Configured remotes are listed but greyed, “after the MVP”, with a preview of a remote row and its Pull and insert.
  • Installation media collection: Insert into… (a menu of the drives that fit) and Add to machine… are enabled, and disabled only with a short reason. Make transfer media… and Export… still say “not available yet”.
  • Pending inserts: a stopped machine shows them in its details, in the drive chips (“at Start”) and in the Media menu. A halted machine takes the disk at once, and Send Ctrl+Alt+Del boots from it.

Revision 1 — out of scope

  • Remote search, remote rows and Pull and insert: after the MVP, with Remotes and the registry catalogue. This mock-up only reserves their place.
  • Showing the library beside a running machine; the library still shows only while no machine runs.
  • CD-ROM insertion, Make transfer media…, Export…, editing a set’s metadata, and real cover art (covers and attachments come with the registry catalogue).
  • A Previous disk command; Next disk keeps cycling through the catalogue as today.

Revision 1 — proposed, confirmed on 2026-11-15

  1. One Insert… per drive replaces Browse / catalogue… and From library…. The drive’s own catalogue becomes the picker’s This machine source, and a disk image file on this computer is Browse for an image file… in the picker’s footer, leading to today’s file flow.
  2. By default only sets that fit the drive are listed. One line, “N don’t fit A: (1.2M) — Show”, reveals the rest, dimmed. A dimmed row says only where it would fit: another drive of the same machine (click or Alt+B switches the drive), or “No drive in this machine takes 1.44M”.
  3. Search uses free words plus field:value (publisher:apogee, format:720k, year:1991..1993, genre:, platform:, label:), the same syntax and ranking tiers as the planned remote catalogue: title first, then publisher, genre, labels and the rest. An empty search lists sets by title.
  4. Facet counts are computed over the current result. Formats the drive doesn’t take are marked “doesn’t fit”.
  5. The disk preselected for insertion is disk 1. If the drive already holds a disk of the same set, the next disk is preselected instead.
  6. Defaults as today: Put all disks in the catalogue, in order is on, and writes go to a journal kept in the machine (“Keep the changes in DOS games”). Disks already in the catalogue keep their own setting.
  7. Into a stopped machine, Insert makes a pending insert. It belongs to the machine and goes in before the first instruction at Start; Eject (“Take out again”) or another Insert into the same drive replaces it. Into a running or halted machine, the disk goes in at once.
  8. Collection Insert into… lists the drives that fit, in every machine, the running machine’s drives first. Because the library shows only while no machine runs, it is a pending insert in practice. Choosing a drive opens the picker on that drive with the set selected, to confirm the disk and write setting.
  9. Collection Add to machine… adds all disks of the set to a drive’s catalogue and inserts nothing. This is machine state, 0 bytes, shown as a catalogue change, and Save as new image… keeps it. I chose this over making it a pending insert, which Insert into… already does.
  10. Insert into… and Add to machine… are disabled only with one short reason: “No machine has a drive for 1.44M disks”, “CD-ROM emulation not available yet” or “Damaged — repair first”.
  11. Keys: Ctrl+Alt+I and Ctrl+Alt+Shift+I (⌘I, ⌘⇧I) open Insert… for A: and B: (existing keys, new dialog). In the picker: typing searches, ↑↓ choose, Enter inserts, Alt+A / Alt+B switch the drive, Esc closes.
  12. Remote rows, after the MVP, say “Not in this library” with the download size, and offer Pull and insert: pull by digest into this library, then insert as above. A private remote first asks for a login, as Get templates does.

Revision 2 — Create from files…: behaviour to approve

  1. Where it starts. Create from files… sits in the picker’s footer beside Browse for an image file…, so every way into the picker reaches it: Media › Insert…, a drive chip’s Insert…, the toolbar’s A: and B:, Ctrl+Alt+I (Shift for B:), Machine › Insert media… and the collection’s Insert into…. Media › Create from files… under each drive’s Insert…, and the same item in a drive chip’s menu, open the picker straight in the Create view for that drive. Files dropped on the main window or on a drive chip do nothing yet (later).
  2. A view of the picker, not a second dialog. The picker’s body becomes the Create view and the Into row stays, so the machine, the drive (also Alt+A / Alt+B) and when the disk goes in are chosen once, as for a set; the formats follow the drive. ‹ Back to search returns with the search and the added items kept; Cancel or Esc closes. I chose this over a dialog of its own because that dialog would need the same target row again, and the shell shows one dialog at a time.
  3. Adding. Add files… opens the system file dialog (several files at once), Add folder… the folder dialog; files and folders dropped on the list are added too. Each row shows where the item lands on the disk, its files and folders, and its size; × removes it. Adding the same item twice changes nothing. Until Create, only names and sizes are read, on the library worker.
  4. Layout on the disk. Everything goes into the top folder. A single added folder becomes the top folder, so its contents go in directly; several items each go into it. The default top folder is the single folder’s name cut to 8.3 (nightfall becomes NIGHTFAL, with no ~1, since nothing else at the root can clash), else empty, which puts everything at the root; it can be edited. Names become 8.3: upper case, characters DOS refuses replaced with _, and a name that does not fit cut to six characters plus ~1 (~2 on a clash). Names that change beyond upper case are listed under DOS names; no long names are written. Host junk is skipped and listed with its reason: .DS_Store, AppleDouble files (._*) and symbolic links.
  5. Format and label. Only the formats the drive takes, the drive’s own first and chosen. The volume label defaults to the top folder name: up to 11 characters, empty writes none.
  6. Fit meter. It counts what DOS counts: the free bytes of a freshly formatted disk (1.44M 1,457,664; 720K 730,112; 1.2M 1,213,952; 360K 362,496), each file rounded up to whole clusters (512 bytes on 1.44M and 1.2M, 1,024 on 720K and 360K), each folder’s own clusters, and the root folder’s fixed entries (224, or 112 on 720K and 360K; the label takes one). The bar shows the files, then the rounding and folders lighter.
  7. Live states. Fits one disk. Does not fit, with the bytes it needs beyond one disk, and a link to a larger format the drive takes when that one fits. A file too large for any disk, named, which disables Create.
  8. Too big for one disk. Both options are shown. Split across N disks keeps folder order and keeps each file whole on one disk; every disk repeats the top folder path and the folders its files need, and its label ends with its number. The plan lists each disk’s label, files, bytes used, and first and last file. The set joins the drive’s catalogue in order, disk 1 goes in, and Media › Next disk swaps. A note gives the XCOPY command that rebuilds the tree on C:, one disk at a time. Copy into C: is greyed, “later”: it writes the files into the machine’s fixed disk as a new layer, a separate and bigger feature.
  9. Create and insert. The image, or each image of a split, is built in memory, stored once by its SHA-256 and becomes one of the machine’s own disks, as a browsed image file does: it joins the drive’s catalogue as a read-only base, and writes go to the machine’s journal or are refused, as chosen. Running or halted, it goes in now; stopped, it is the drive’s pending insert for the next Start, and the stopped machine owns the image by its SHA-256 until then, without the library. Also keep in the library as an installation media set (on for a split, off for one disk, until changed) also adds it to Installation media as a private set, such as azuramon:1.0 titled AZURAMON, so every machine’s Insert… lists it. Left off, the disks belong to that machine alone and are removed with it.
  10. Deterministic. The same files with the same names, top folder, label and format give the same image bytes and SHA-256, in whatever order they were added: host times are not kept, every entry gets one fixed date, and nothing random goes in. The window uses the same builder as the new command-line tool.

Revision 2 — out of scope

  • Copy into C: (shown greyed), editing a DOS name by hand, long file names, and CD-ROM images.
  • Writing an image file on this computer without a machine: the command-line tool does that.

Decided by the maintainer (2026-11-17)

  1. Split first. Split across N disks ships now. Copy into C: stays greyed, “later”, a feature of its own.
  2. Default top folder as drawn: a single added folder’s name cut to 8.3, else empty (the root).
  3. Keep in the library is on for a split and off for one disk, until the user changes it.
  4. Entry points: the picker’s footer, and Create from files… in the Media menu and a drive chip’s menu. Dropping files on the main window or a drive chip comes later.
  5. A created disk for a stopped machine: the machine owns the image by its SHA-256 until Start; the library is not needed.
  6. Split order: folder order, as drawn.
