Design mock-up — approved by the maintainer on 2026-11-15. File › Get templates… and the empty library that offers it. Sample data only: the two templates and their descriptions are the real 1.0.0 generation, but digests, sizes and timings are illustrative, and nas.example:5000 is a placeholder. Nothing connects to a registry or writes files.

Decisions in this mock-up

  • Two ways in: File › Get templates…, and a Get templates… button in the library while it holds no machine image. Firmware packages and installation media do not count as machine images. The empty state contacts no registry; the dialog lists only when it opens.
  • The dialog reads one place: unemu/ on the default registry, and names that registry. Firmware packages and test repositories there are not offered.
  • One row per template, at the version latest names, else its newest release; Image › Pull… gets the others. A row shows a checkbox, name, tag, title, description and size. Nothing is chosen in advance, and the button counts the choice.
  • A template already in the library cannot be chosen; the row says which tag it is under. When that local tag names another image, the row is disabled and points to Image › Pull… with another local tag.
  • Get pulls the chosen templates one after another, each by the digest the list showed. One progress bar covers them all, with a row per template and Cancel. Cancel stops the running pull at its next read and stops the queued ones before they start. Their local tags are not written; fetched blobs stay in the store.
  • An unreachable registry, a refused or missing login, or a registry without a catalog ends the listing with one message and Try again. The two login cases also offer Log in…. Closing the dialog stops a listing.
  • When the pulls are done, the dialog offers Close, or Back to the list, which lists again so the new templates show as in the library. The status bar names what was added.
