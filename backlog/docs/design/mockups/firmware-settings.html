Design mock-up — approved by the maintainer on 2026-11-15, all “please confirm” items included with the proposed options (Switch to… opens Settings with the choice made; Machine files becomes the reduced collection). Firmware choices in Settings… on a machine and on an image, a “newer version available” hint for superseded firmware, and the reduced Machine files collection. Real catalogue ids, firmware names and SHA-256 prefixes; image digests, sizes and dates are illustrative. Actions are previews: nothing runs, pulls, imports or publishes. Built on the approved machines, firmware (revision 3), new-machine, save-as-image and main-window mock-ups; everything not shown here stays as they show it.

Where a firmware change goes

Settings… on a machineFirmware joins the editable settings. It changes this machine only, from its next start. C:, its disk layers and its inserted media stay.
Settings… on an imagePublishes a new image revision under a new tag. No existing tag changes, and machines keep the image they run.
Superseded firmwareStill listed, and machines on it still start. It is marked “(superseded)” and never preselected, and the details pane offers the release that replaces it.
Machine filesThe TOML format stays for the command line, the tests and machines/. The desktop only lists files and turns one into an image.

Today

  • Settings… on an image refuses every firmware edit: “Firmware stays as the image stores it; Settings on an image changes hardware only.” Settings… on a machine shows its firmware read-only.
  • DOS games, a machine from open-at-games:1.1.0 with games installed on C:, runs the superseded open AT BIOS 1.0.2-unemu.2 and cannot be switched. 1.0.2-unemu.3 clears memory above 1 MiB on POST, which fixes “no XMS after Ctrl+Alt+Del” with FreeDOS.
  • Machine files have property sheets of their own, which write a local child file next to the original.

Changes in this design

  • Settings… on a machine: the Firmware tab becomes editable. It has a System BIOS choice and, when the machine has a video card with a BIOS, a Video BIOS choice. Each lists the catalogue entries that fit the board and says why one cannot be used. The change applies at the machine’s next start, while C:, its disk layers and its inserted media stay. It shows under Settings that differ from the image. Save as new image… writes it into the new image, and Reset to image… drops it like any other setting.
  • CMOS: with the same CMOS layout (1.0.2-unemu.2 to 1.0.2-unemu.3), the machine’s CMOS stays. With another layout (open AT BIOS to IBM 5170 BIOS), the sheet shows one warning: CMOS settings are reset at the next start. The mock-up controls show both.
  • A ROM not in the store: OK pulls an open package that the registry offers. A ROM that no registry offers is listed as unavailable, with its reason and Import ROM folder….
  • Settings… on an image: firmware is editable here too. Review changes… asks for the tag of the new revision and suggests one. Every existing tag is refused. An open image that takes a user-supplied ROM becomes user-supplied. A revision of an official template stays local.
  • Newer version available: a machine’s or an image’s details pane says when its firmware is superseded. Its Switch to 1.0.2-unemu.3… button opens Settings with that choice already made. Rows carry a small “↑ newer BIOS” badge.
  • Machine files: the collection becomes a plain list with one action, Create image…. It imports the file as an image and can also create a machine. Settings… and Start on a file leave the desktop.
  • Firmware collection: a Status column. The superseded package reads Superseded by 1.0.2-unemu.3.

Out of scope

  • Changing disks, the disk controller or a geometry in a way that invalidates disk layers. C: and its controller stay read-only in the sheet, as approved.
  • Upgrading many machines in one step. Each machine or image is switched on its own.
  • Registry-side changes. Nothing on registry.unemu.dev is retagged, marked or deprecated, and the official templates stay read-only there.
  • Rebasing a machine onto a newer image such as open-at-games:1.1.1. A firmware switch is a setting of the machine, not a rebase.
  • Option ROM choices. The XTIDE build follows its disk adapter.

Proposed — please confirm

  1. Choices. System BIOS lists the catalogue entries whose boards include the machine’s board (ibm-5170 here), grouped by family. The entries in one group share a CMOS layout. Video BIOS is shown only for a machine whose video card has a BIOS, and lists the entries for that card. An MDA machine shows “None”.
  2. Superseded entries can still be chosen, so a machine can stay on one or go back to it. They are marked “(superseded)” and listed after the release that replaces them. They are never preselected: not as the default for a new card, for New machine…, or for a choice that has become invalid. While one is chosen, the field names its replacement and has a Use … link.
  3. CMOS layout becomes a field of each system BIOS entry in the catalogue. The layouts are open AT BIOS, Kiselev Xi 8088 (its checksum covers 10h–20h; the open AT BIOS’s covers 10h–2Dh), IBM AT and Landmark ROM POST. Within one layout the machine keeps its CMOS. A change of layout resets the CMOS at the next start to the bytes derived from the configuration, as on a new machine, and the date, time and SETUP choices are lost. The sheet shows one warning, and OK asks nothing more.
  4. A ROM not in the store — proposed: the same rule as New machine…. A package that a configured registry offers can be chosen, and OK (or Publish revision) pulls it first and checks every byte. Open packages live under unemu/firmware/ on registry.unemu.dev; a private registry of yours counts too. If the pull fails, nothing is saved. A ROM that no registry offers is unavailable, with its reason and Import ROM folder…, which opens the Firmware library’s import over the sheet. “In the store” means its bytes are in the local store, from a firmware package or from any image.
  5. Tags. Publish revision never overwrites a tag, so every existing tag is refused, including latest and other non-version tags. The approved Move tag? question stays only for Save as new image…. For your own repository, the suggested tag is the next minor version (ibm-at-dos:1.2.0). For an official template, it is the source version with a local suffix (open-at-games:1.1.0-local.1), so no later official release can clash with it.
  6. Official templates. A revision of an unemu/ template is written to the local store only. The review says that unemu/ is read-only for you and that Push… can send the revision to a namespace of your own.
  7. User-supplied. An open image that takes a user-supplied ROM becomes user-supplied, and the review says so in one line: it can be pushed only to a namespace marked private, never to unemu/. On a machine, the sheet says the same about a later Save as new image….
  8. Switch to … — proposed: open Settings with the choice made, on the Firmware tab, so the CMOS line and any conflict are visible first. Nothing changes until OK, or until Review changes… and Publish revision on an image. The alternative is a confirm dialog that applies the switch at once.
  9. Hint text comes from a short reason that the catalogue stores with each superseded entry. On an image, when a newer tag of the same repository already uses the replacement (open-at-games:1.1.1), the hint links to it. The hint cannot be dismissed; it stays while the firmware is superseded.
  10. Row badge — proposed: yes. A quiet “↑ newer BIOS” badge appears in a machine’s State and after an image’s name, with the hint as its tooltip. It is not a warning, because the machine still starts.
  11. Machine files — recommended: the reduced collection, a plain list with one action, Create image… (repository, tag, title, and optionally a machine). File › Open machine file… (Ctrl+O) adds a file to the list and opens Create image… on it. Start and Settings… on a file leave the desktop; the window’s --machine option still runs a file, for development. Alternative: remove the collection, let File › Import image… take machine files, and drop Machine files from the library groups of decision-29.
  12. Firmware collection: the row of a superseded package shows Superseded by … in a Status column. Nothing else in the approved Firmware collection changes.
