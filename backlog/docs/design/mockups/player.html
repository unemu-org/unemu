What each part is made from

  • Nothing in the player names a platform. The filters come from each core’s platform and content kinds; the title is the content’s own title or the file’s name, then the platform’s name; the menus, the status line and the Input dialog come from the running machine’s description.
  • The picture keeps the shape the machine states. The sample is 256 × 240 with the shape 128:105, and its visible part is 256 × 224 from row 8. With Show overscan off the screen shows the visible part, 64:49; with it on, the whole picture, 128:105. The pixels keep their shape either way. With Integer scale the height is a whole multiple of the rows shown.
  • The library does not list what was opened from a file, and there is no list of recent files.
  • The picture is a drawing made for this page. The rows above and below the white frame are the overscan, drawn as coloured blocks because a machine may leave anything there.

Decided here, where the design left it open

  1. Open… sits in File just above Open machine file…, and is also offered while a machine runs (it then asks to stop it). The file dialog opens on “All supported files”.
  2. Disabled Open… explains itself the way every disabled item of the shell does today, by its hover text: “No core in this release opens files”.
  3. Title: content — platform — unemupc, the pattern of today’s machine — image — unemupc.
  4. Status line keeps today’s cells and order: the message, a light with Running or Paused where Power is, a chip per removable slot where the drive chips are, the platform and the content’s name where the processor and EMS cells are, then sound and speed.
  5. Present or absent, not greyed. Reset, Save state and Load state, Input…, Show overscan and the slot menus appear only for a machine whose description offers them. Load state alone is greyed, with its reason, until a state has been saved for this content.
  6. Keys. Pause, Stop, Mute, Full screen and Hold for Unlimited keep their chords. Reset takes Ctrl+Alt+End, the place of Send Ctrl+Alt+Del. The first removable slot takes Ctrl+Alt+E and Ctrl+Alt+F, the second the same with Shift. Proposed new: Ctrl+Alt+S saves the state and Ctrl+Alt+L loads it.
  7. View. “Scale to window, 4:3” reads “Scale to window” in the player, since the shape is the machine’s. Fast forward stays what it is today: the Hold for Unlimited row of View › Speed.
  8. Toolbar. The same toolbar: the PC’s buttons (A:, B:, Eject, Settings, Layers) stay in place and greyed, so nothing jumps, and the Ctrl+Alt+Del button reads Reset.
  9. Slot menu. Eject, Next in catalogue, then the catalogue’s entries with a dot on the one in the slot. No Insert…: adding a medium from a file comes later. An empty slot greys Eject.
  10. Input dialog. Keys are shown by readable names (Arrow Up, Shift Right), derived from the names the preferences file uses. A pressed key replaces the row’s keys and is taken away from any other control that had it. Defaults restores every player. Nothing changes until OK.
  11. Message boxes carry the refused command as their title (Open, Load state) and one OK. The stop prompt is today’s, word for word, with the content’s name in it.
  12. Wording proposed here, where the design gives none: the “already running” box, the second sentence of “needs more than itself”, and the lead-in to a core’s own message. A file that cannot be read, and a core named on the command line that is not compiled in, use the same box.

Asked, and decided by the maintainer with the recommendation (2026-11-18)

  1. Where do the player’s menus sit? Drawn: the player’s Machine menu takes the place and the name of the PC’s Machine menu, and each removable slot gets a menu of its own, named by the slot’s label, where Media is. The option “Slots as one Media menu” shows the alternative: one Media menu with a section per slot, as the PC’s Media menu has a section per drive. Recommendation: one Media menu. The menu bar then has the same words for every machine, a machine with four slots does not push View off a laptop screen, and the PC’s drives fit it unchanged the day the PC runs on this path. A machine with no removable slot has no Media menu.
  2. Do Save state and Load state get toolbar buttons? Recommendation: no, not yet. There is one quick slot, the menu and two chords reach it, and the toolbar already fills one line at the default width. Add buttons when named slots arrive.
  3. Who owns Ctrl+O? Today it belongs to Open machine file…. Recommendation: Open… takes it, as the common case, and Open machine file… goes without a key.
  4. Open… while a machine runs: ask to stop first, or check the file first? Recommendation: check first. A file that would be refused then shows its refusal and leaves the running machine alone; the stop prompt appears only for a file that can start.
  5. Clearing a binding in the Input dialog. The design gives the dialog rows, a key press and Defaults. Recommendation: while a row waits for a key, Esc leaves it as it was and Delete clears it, so those two keys cannot be bound; and a key press replaces the row’s keys instead of adding a second one. One line of text under the list says so.
