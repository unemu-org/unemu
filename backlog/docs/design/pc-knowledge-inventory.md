**(a) Things that legitimately stay in the front end**

- **OCI image store, manifests, hashes, compression, tags, registry and local catalogue:** these describe storage and publication, not emulated hardware. (`image-store/Cargo.toml:10`, `image-store/src/library.rs:2`, `library-model/src/platform.rs:26`.)
- **Layers, sparse bases, journal bytes and current-byte readers:** retain byte-format parsing/composition where these are owned storage formats; remove PC geometry limits, CMOS meanings and device associations. Contract 0.5 explicitly assigns current-byte composition to the front end. (`pc-image/src/disk.rs:32`, `pc-image/src/zero.rs:60`, `API/docs/decisions/0001-offline-media-and-export.md:22`.)
- **Recipe syntax, locks, deterministic transforms, source acquisition and publication:** hardware vocabularies already enter through providers. (`recipe/Cargo.toml:10`, `recipe/src/provider.rs:47`, `recipe/src/provider.rs:142`, `recipe/src/steps.rs:262`.)
- **FAT reader/builder as an explicit filesystem tool:** **ASSUMED appropriate**, provided PC geometry/BPB/boot behavior becomes an explicitly selected profile; the present module identifies itself as that PC profile. (`media/src/fat12/mod.rs:39`, `media/src/fat12/boot.rs:2`.)
- **Firmware/media package envelopes, provenance, licences and attachments:** generic fields and byte identities can stay; interpreting board fit, chip lanes and firmware roles belongs behind core-supplied rules. (`image-store/src/firmware.rs:18`, `:33`, `:77`; `image-store/src/media_set.rs:14`, `:47`.)
- **Generic library widgets, registry models, player and launch orchestration:** these already accept platform data or contract objects. A BIOS example in a widget comment is not hardware behavior. (`library-model/src/platform.rs:20`, `library-ui/src/table.rs:278`, `player-ui/src/lib.rs:195`, `core-launch/src/launch.rs:683`.)
- **Historical platform aliases and editorial catalogue metadata:** aliases are explicitly the front end’s concern; software titles/requirements can remain uninterpreted metadata. (`API/src/core.rs:255`, `image-store/src/platform.rs:12`, `image-store/src/metadata.rs:76`, `:124`.)
- **Compiled-in core registration and release source notices:** concrete factory references at the composition root are legitimate; callers should subsequently use `dyn Core`. (`platforms/src/lib.rs:25`, `:111`.)
